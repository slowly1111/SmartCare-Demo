# [智能托管助手] 版本规划路线图

## 1. 产品概述

* **核心定位**：中小学托管机构的降维打击效率工具。
* **核心价值**：
1. **安全**：两段式考勤（校门接 -> 机构到），杜绝走丢风险。
2. **效率**：连拍作业 -> 自动拼版 PDF，解放老师双手。
3. **感知**：家长端数字化日报，提升服务专业度。


* **目标用户**：托管老师（高频操作）、家长（查看）、校长（后台管理）。

## 2. 核心需求清单 (优先级排序)

1. **P0 (生死线)**：老师端极速连拍 + 后端 PDF 生成。
2. **P0 (生死线)**：老师端两段式考勤（待接/途中/入班）+ 一键入班。
3. **P0 (生死线)**：家长端每日动态时间轴（查看 PDF）。
4. **P1 (重要)**：学生档案管理（历史记录、请假标记）。
5. **P1 (重要)**：基础身份系统（老师登录、家长绑定）。
6. **P2 (次要)**：校长 Web 管理后台（批量导入、班级设置）。
7. **P2 (次要)**：微信服务号通知推送。

## 3. 版本规划路线图

### V0.1 MVP - [验证核心闭环]

> **目标**：在一个真实班级中跑通“考勤+作业”全流程，老师能用，家长能看。

**功能清单**：

1. **老师端-工作台**：
* 学生列表展示（含状态球）。
* 两段式考勤交互（灰->黄->绿）。
* “一键全部入班”逻辑。


2. **老师端-相机**：
* 全屏取景、不跳转连拍、缩略图预览。
* 图片压缩上传（云存储）。


3. **后端服务 (云函数)**：
* **核心算法**：接收图片 -> 拼图 -> 生成 PDF -> 返回 FileID。


4. **家长端-日报**：
* 只做最简单的“输入学生姓名/手机号”查看（暂不做复杂登录）。
* 时间轴展示：考勤状态 + 作业 PDF 下载/预览。



**不做什么 (关键)**：

* **不做 Web 管理后台**：学生数据直接在微信开发者工具的“云开发控制台”里手动录入 JSON。
* **不做“请假/历史”**：V0.1 默认全员出勤，暂不看历史数据。
* **不做多班级切换**：硬编码只显示一个班级。

**验证点**：老师能否在 1 分钟内完成全班点名？生成的 PDF 在家长手机上能否正常打开？
**预计工作量**：10 - 14 天

---

### V0.2 - [数据资产化]

> **目标**：完善异常处理和数据沉淀，让产品具备“长期使用”的价值。

**功能清单**：

1. **老师端-异常处理**：
* 长按状态球 -> 标记请假。
* 顶部统计筛选条（全部/待接/请假）。


2. **学生档案页**：
* 点击头像进入详情。
* 展示历史 PDF 列表（按日期倒序）。
* 简单的编辑功能（修改姓名、绑定家长手机）。


3. **账号体系升级**：
* 家长端接入微信登录 -> 自动匹配绑定的手机号 -> 显示对应孩子（不再需要手动搜）。


4. **首页多班级**：
* 支持切换“午托班/晚托班”。



**不做什么**：

* 仍然不做 Web 端的批量导入，数据量不大时老师在手机端一个个加，或者开发者帮忙导。

**验证点**：遇到学生请假时，老师操作是否顺畅？家长能否顺利看到自己孩子的历史错题？
**预计工作量**：7 - 10 天

---

### V0.3 - [运营自助化]

> **目标**：解放开发者（你自己），让机构校长能自助配置数据。

**功能清单**：

1. **PC Web 轻量后台**：
* 校长登录。
* Excel 批量导入学生名单。
* 机构品牌设置（上传 Logo，用于 PDF 页眉）。


2. **老师端-快捷入口**：
* 首页金刚区：添加学生、班级设置。


3. **班级广播功能**：
* 老师发布“晚餐/午休”集体照，家长端同步显示。



**验证点**：校长能否在不求助你的情况下，独立完成新学期的班级初始化？
**预计工作量**：5 - 7 天

---

### V1.0 - [正式商用版]

> **目标**：优化体验，接入微信生态通知能力，达到对外售卖标准。

**功能清单**：

1. **消息推送**：
* 接入微信“订阅消息”或服务号模板消息（到校提醒、报告生成提醒）。


2. **性能优化**：
* 图片上传的断点续传（应对电梯/校门口弱网）。
* PDF 生成速度优化。


3. **UI/UX 打磨**：
* 增加加载动画、操作音效、空状态插画。
* 帮助文档与引导页。



**验证点**：App 在弱网环境下是否稳定？消息推送触达率如何？
**预计工作量**：7 天
