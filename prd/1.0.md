# 产品需求文档：智能托管助手 (SmartCare) - MVP v1.0

## 1. 综述 (Overview)

### 1.1 项目背景与核心问题

传统托管机构老师在放学高峰期面临"接送安全"与"作业反馈"的双重压力。目前主要依赖微信群发消息，存在效率低（一张张发图）、信息杂（家长爬楼难）、隐患大（接送状态不透明）等痛点。

本项目旨在通过 **小程序 + 云开发** 技术，用"极速连拍"和"两段式考勤"降维打击现有流程，为老师提效，给家长确定性。

### 1.2 核心业务流程 / 用户旅程地图

1. **阶段一：安全接送（老师端）** - 校门口极速点名（灰->黄），进班后一键入班（黄->绿），确保接送闭环。
2. **阶段二：作业归档（老师端/云端）** - 辅导期间连拍错题，云端自动拼图生成 PDF 报告。
3. **阶段三：家校互通（家长端）** - 家长通过手机号登录，查看孩子今日安全动态及作业报告。

### 2.4 老师工作台与考勤

#### **US-01: 老师工作台与状态管理**

* **价值陈述**:
  * **作为** 托管老师
  * **我希望** 在一个页面能一眼看到班级所有人的实时状态，并能通过简单的点击完成状态变更
  * **以便于** 在嘈杂的校门口和忙碌的教室里快速完成考勤，不出安全事故

* **业务规则与逻辑**:

1. **页面布局 (参照已确认 UI)**:
   * **顶部统计筛选条**: 必须包含 **[全部] [待接] [途中] [入班] [请假]** 五个 Tab
   * **学生卡片**: 展示头像、姓名、作业归档标、**智能状态球**
   * **底部操作栏**: 左侧 [📷 拍作业]，右侧 [✅ 一键全部入班]

2. **智能状态球逻辑 (核心)**:
   * **点击交互**: 三态循环 `⚪ 待接 (0)` -> `🟡 途中 (1)` -> `🟢 入班 (2)` -> `⚪ 待接 (0)`
   * **长按交互 (1秒)**: 弹出菜单，选择 `⛔ 标记为请假 (3)`

3. **一键全部入班**:
   * 批量更新状态为"途中"的学生为"入班"

* **验收标准**:
  * **场景1: 校门口接人**
    * GIVEN 学生"谭圣涵"当前是"待接"
    * WHEN 老师点击他的状态球
    * THEN 状态球变为黄色"途中"

### 2.5 极速连拍与作业归档

#### **US-02: 极速连拍与作业归档**

* **价值陈述**:
  * **作为** 托管老师
  * **我希望** 能连续拍摄多张错题而不被打断，拍完自动归档，并能快速给家长反馈
  * **以便于** 节省在相册里选图、发微信的时间，同时让家长感受到老师的关注

#### **2.5.1 相机页双通道入口设计 (核心创新)**

* **设计理念**: **入口分流，出口统一** —— 无论有没有错题，老师都能顺畅完成反馈

* **页面布局线框图**:
```text
+-------------------------------------------+
|  ←          为 谭圣涵 拍摄                 |
+-------------------------------------------+
|                                           |
|               [ 相机取景框 ]               |
|                                           |
+-------------------------------------------+
|        [ 数学 ]  [ 语文 ]  [ 英语 ]         |
+-------------------------------------------+
| [ 缩略图预览条: (空) 或 (照片1, 照片2...) ] |
+-------------------------------------------+
|                                           |
|  [🎉 今日全对]     (○)      [ 提交 (0) ]   |
|    金色入口       快门键      绿色入口     |
|                                           |
+-------------------------------------------+
```

* **业务规则与逻辑**:

1. **左侧金色按钮「🎉 今日全对」**:
   * **功能**: 无需拍照，直接打开归档弹窗
   * **场景**: 学生今天作业全对，无错题需要归档
   * **弹窗状态**: 标题为"🎉 确认全对归档"，金色主题

2. **中间快门按钮**:
   * **功能**: 拍摄错题照片，飞入底部预览条
   * **交互**: 点击后闪光动画 + 震动反馈

3. **右侧绿色按钮「提交 (n)」**:
   * **功能**: 必须先拍照 (n>0) 才能点击，打开归档弹窗
   * **弹窗状态**: 标题为"📦 确认错题归档"，绿色主题

#### **2.5.2 学习反馈模块 (归档弹窗内)**

* **设计理念**: **标签为主 (80%) + 文字为辅 (20%)** —— 让老师1秒完成评价，避免"必填小作文"

* **弹窗布局线框图**:
```text
+-------------------------------------------+
|  📦 确认错题归档  /  🎉 确认全对归档        |
+-------------------------------------------+
|                                           |
|  🏷️ 今日表现 (点选)                        |
|  [👍 书写工整] [⚡ 速度快] [🧠 思路清晰]    |
|  [🐢 有点拖拉] [💪 需要鼓励]               |
|                                           |
|  💬 老师留言 (选填)                        |
|  ┌─────────────────────────────────────┐ |
|  │ 例如：今天背诵课文非常流利...         │ |
|  └─────────────────────────────────────┘ |
|                                           |
|  📄 已拍摄 3 张数学作业 / ✨ 将生成表扬卡   |
|                                           |
|     [ ✅ 确认发送给家长 ]                  |
+-------------------------------------------+
```

* **字段定义**:
  | 字段 | 类型 | 必填 | 说明 |
  |------|------|------|------|
  | 表现标签 | multi-select | ❌ | 预设5个标签，支持多选 |
  | 老师留言 | textarea | ❌ | 最多200字，用于个性化沟通 |

* **两种模式对比**:
  | 特性 | 普通归档模式 | 全对归档模式 |
  |------|--------------|--------------|
  | 入口 | 右侧"提交"按钮 | 左侧"今日全对"按钮 |
  | 前置条件 | 必须先拍照 | 无需拍照 |
  | 弹窗主题色 | 🟢 绿色 | 🟡 金色 |
  | 文件提示 | "已拍摄 X 张，准备生成 PDF" | "✨ 将生成表扬卡" |
  | 默认标签 | 无 | 自动选中"书写工整" |

### 2.6 历史记录页面 (History Records)

#### **US-02-C: 历史记录与考勤统计**

* **价值陈述**:
  * **作为** 托管老师/机构管理者
  * **我希望** 能按月份、班级查看历史考勤统计和作业报告汇总
  * **以便于** 回溯历史数据、应对家长查询、月底统计报表

* **核心用途**:
  * **场景 A**: 家长问"上周三我孩子来了吗？"，老师点这里查
  * **场景 B**: 校长月底要统计所有人的出勤天数，点这里看总表

#### **2.6.1 列表页布局 (List View)**

```text
+-----------------------------------+
| <           历史记录              |
+-----------------------------------+
| [ 2026年2月 ▼ ]   [ 全部班级 ▼ ]   |
+-----------------------------------+
| [📊 2月统计概览]                   |
|  5天上课 | 96%出勤 | 43份报告     |
+-----------------------------------+
|                                   |
|  05  一年级午托精选班           > |
|  周三  2026-02-05                 |
|  -------------------------------  |
|  应到 20 | 实到 19 请假 1  📄 PDF 19 |
|  -------------------------------  |
|                                   |
+-----------------------------------+
|                                   |
|  04  一年级午托精选班           > |
|  周二  2026-02-04                 |
|  -------------------------------  |
|  应到 20 | 实到 20 请假 0  📄 PDF 20 |
|  -------------------------------  |
+-----------------------------------+
```

* **列表项数据行说明**:
  * **应到**: 当日班级快照人数 (从 `history_stats.snapshot_total` 读取)
  * **实到**: 当日实际签到人数 (绿色高亮)
  * **请假**: 当日请假人数 (有值时橙色高亮)
  * **缺勤**: `应到 - 实到 - 请假` (有值时红色高亮)
  * **PDF**: 当日生成的作业报告数量

#### **2.6.2 详情页布局 (Detail View - 抬头强化版)**

```text
+-----------------------------------+
| <         2026年02月05日          |
+-----------------------------------+
|  周三 · 一年级午托精选班          |
+-----------------------------------+
|                                   |
|  👥 应到全员                  20人 |  <- 大标题，24px加粗
|  -------------------------------  |  <- 分割线，强调总与分
|                                   |
|  +--------+  +--------+  +------+ |
|  |   19   |  |    1   |  |   0  | |
|  |  实到  |  |  请假  |  | 缺勤 | |
|  | (绿底) |  | (黄底) |  | (红底)| |
|  +--------+  +--------+  +------+ |
|                                   |
|  [📌 请假: 赵铁柱 (感冒发烧)]     |
|                                   |
+-----------------------------------+
|  📝 作业概览                      |
|                                   |
|  生成PDF数量               19 份  |
|  -------------------------------  |
|  已发送家长                19 份  |
|  -------------------------------  |
|  存储空间占用             12.3 MB |
|                                   |
|  [ 📤 批量导出/转发本日PDF ]      |
+-----------------------------------+
```

* **业务规则与逻辑**:

1. **应到人数 (Total Count) - 关键**:
   * **必须是快照**: 读取自 `history_stats` 表的 `snapshot_total` 字段
   * **严禁实时计算**: 不能用当前班级人数，因学生可能随时增减

2. **缺勤计算**:
   * 公式: `缺勤 = 应到 - 实到 - 请假`
   * 如果 > 0，数字标红提醒异常

3. **批量导出**:
   * 点击按钮 -> 打包当日所有 PDF -> 触发下载/转发

* **验收标准**:
  * **场景1: 查询历史**
    * GIVEN 家长问"上周三孩子来了吗"
    * WHEN 老师打开历史记录，筛选日期
    * THEN 看到当天该班级的详细考勤情况
  * **场景2: 月度报表**
    * GIVEN 校长需要统计2月出勤率
    * WHEN 筛选2月、全部班级
    * THEN 顶部统计卡片显示"5天上课、96%出勤、43份报告"

## 4. 数据模型 / 接口契约 (Data Contracts)

### 4.1 核心数据库设计 (Cloud Database)

**集合 1: `students` (学生表)**
| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 系统生成 |
| `name` | string | 学生姓名 |

| `parent_relation` | string | 家长称呼 (爸爸/妈妈等) |
| `status` | number | 今日状态 (0待接/1途中/2入班/3请假) |
| `parent_openid` | string | 家长微信 OpenID (绑定后填入) |

**集合 2: `classes` (班级表)**
| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 系统生成 |
| `name` | string | 班级名称 |
| `type` | string | 托管类型 (午托/晚托/全托/兴趣班) |
| `time` | string | 上课时间描述 |
| `student_count` | number | 学生人数 (冗余缓存) |

| 字段 | 类型 | 说明 |
|------|------|------|
| `student_id` | string | 关联学生 |
| `action` | number | 1=接, 2=入, 3=请假 |
| `timestamp` | datetime | 操作时间 |
| `operator` | string | 老师ID |

| 字段 | 类型 | 说明 |
|------|------|------|

| `date` | string | 日期 (YYYY-MM-DD) |
| `subject` | string | 科目 |
| `image_file_ids` | array | 原始图片路径 |
| `pdf_file_id` | string | 生成的 PDF 路径 |
